**R1：打包清理路径缺少边界校验。**

位置：[build-packages.ps1:8](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/build-packages.ps1:8>)。

`$Version` 直接拼接进 `publish\$Version`，随后对该路径执行 `Remove-Item -Recurse -Force`。传入 `-Version '..'` 时，规范化目标恰好是整个项目根目录；`..\..` 还会越过项目边界。脚本也使用支持通配符的 `-Path`。

验证仅调用 `Path.GetFullPath`，结果为 `C:\Users\Lenovo\Documents\Codex\地平线浮窗`，没有调用删除命令。应在任何清理之前校验版本格式、拒绝路径分隔符和通配符，检查规范化后的目标严格位于 `publish` 内，并使用 `-LiteralPath`。最好先完成临时目录构建，再替换对应版本的产物。

**R2：dotnet10.cmd 没有传回实际执行结果。**

位置：[dotnet10.cmd:8](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/dotnet10.cmd:8>)、同文件第 16 行的第二条执行路径。

括号块里的 `%errorlevel%` 在块执行前展开，`exit /b %errorlevel%` 使用了旧值。对不存在的 DLL 执行 `dotnet exec`，SDK 本身返回 `-2147450751`，包装脚本返回 `0`。本次第一次测试因沙箱限制而中止时，包装脚本同样返回了 0。因此自动化不能可靠地据此判断测试或发布是否成功。

建议将 SDK 选择与执行分开，使 `exit /b %errorlevel%` 在执行后的独立语句中求值，或用子程序传回退出码。另应在打包脚本中显式检查 `dotnet publish` 的退出码，并统一 SDK 入口；当前脚本直接使用 PATH 中的 `dotnet`。

证据：[wrapper-exit.json](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/artifacts/review-20261120/wrapper-exit.json>)。

**R3：歌曲 ID 不匹配时，错误缓存使回退搜索失效。**

位置：[NeteaseOfficialResolver.cs:65](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/Services/NeteaseOfficialResolver.cs:65>)。

`ResolveAsync` 在 `ShouldAcceptPreferredIdResult` 之前调用 `CacheIfCoverAvailable(trackKey, byId)`。不匹配的结果被写到正在查询的曲目键下；校验拒绝后，紧随其后的 `_trackCache` 查询又将它直接返回。外层尝试去掉 ID 再搜索时，仍会命中同一错误缓存。

模拟正确曲目 ID 为 1、过期提示 ID 为 2，ID 接口返回带封面的无关歌曲。两次调用（有提示、无提示）均返回 2，搜索请求次数为 0。用户会看到错误封面，错误 ID 也可能继续用于取词。应先确认匹配再写入曲目缓存，并保证拒绝后的搜索不读取本次无效结果。

**R4：歌词失败重试没有接入轮询。**

位置：[MainWindow.Playback.cs:221](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/MainWindow.Playback.cs:221>)。

轮询仅在 `TrackVersion` 变化时调用 `RefreshCurrentTrackAsync`，歌词查询也只从该路径触发。`LyricsService` 虽然有失败后 1.5 秒的重试间隔，但它不会自行调度重试。网络临时失败后，只要歌曲元数据不变，整个曲目期间就可能一直无歌词。

复现将首次查询设为失败，之后设为成功，并推进歌词服务时钟超过重试间隔；连续刷新相同曲目三次，查询次数仍为 1、`HasLyrics=false`。手动刷新后立即变为 2 次且成功取得歌词。应独立调度当前曲目的歌词补取，保留现有节流、去重及过期请求保护。

**R5：暂停隐藏规则被后续曲目展示覆盖。**

位置：[MainWindow.Playback.cs:570](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/MainWindow.Playback.cs:570>)；相关顺序在第 167–223 行。

快照处理先执行暂停隐藏规则，之后处理曲目变化并无条件 `ShowTrackAsync`。开启暂停隐藏时，启动后读到已暂停的曲目、或播放器在暂停状态下切歌，会再次展示浮窗。后续暂停位置和状态不变，`TimelineVersion` 也不变，隐藏规则不会再次执行。

模拟 SMTC 已暂停的新曲目，并继续刷新相同状态，结果 `IsPlaying=false`、`IsContentVisible=true`。常驻模式下会持续显示。应在曲目显示入口同时检查暂停条件，或在曲目更新后统一计算最终显隐状态。

**R6：无曲目时未清理浮窗内容。**

位置：[MainWindow.Playback.cs:477](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/MainWindow.Playback.cs:477>)。

`track == null` 调用 `ResetTrackDisplay`，只清空主界面和歌词状态，没有隐藏浮窗或取消待展示的歌曲。关闭播放器后，主界面显示“未检测到网易云歌曲”，常驻浮窗仍显示上一首歌及封面。

复现将正常曲目切换为 `null`，主界面已清空而浮窗仍可见，标题仍为测试歌曲。应在确认会话消失后统一清理浮窗展示和动画队列；若需要容忍切歌瞬间的空快照，可使用有限宽限期。

**R7：SMTC 同曲目的封面更新没有常规刷新路径。**

位置：[MainWindow.Playback.cs:547](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/MainWindow.Playback.cs:547>)。

同一首歌仅封面改变时，`TrackVersion` 会增加，但 `displayChanged=false`。后续更新分支被 `!useSmtc` 排除。专门的 SMTC 封面重试只在切歌时启动，且最多尝试六次；晚到的封面或同曲目正常更新因此会永久被忽略，直到再次切歌。

复现先提供红色封面，再以相同标题、歌手和来源提供蓝色封面。主界面实际像素仍为红色，蓝色通道为 0。应允许当前 SMTC 曲目接受后续封面更新，并保留切歌期间防止旧封面闪回的策略。

**R8：状态栏的新文本被自身缓存检查拦截。**

位置：[MainWindow.Playback.cs:809](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/MainWindow.Playback.cs:809>)；相关方法在第 883 行。

`SetStatusIfChanged` 先写 `_lastStatusText=message`，再调用 `SetStatus`；后者看到相同文本立即返回，永远不执行 `StatusText.Text=text`。通过该入口发送的“未读取到会话”“读取数据失败”等消息不会显示。

实际主窗口先显示 `before`，调用 `SetStatusIfChanged("after", true)` 后仍为 `before`。应只由最终更新 UI 的方法维护缓存，并统一错误状态的去重判断。

**R9：更新资源选择忽略运行架构。**

位置：[UpdateService.cs:45](<C:/Users/Lenovo/Documents/Codex/地平线浮窗/Services/UpdateService.cs:45>)。
